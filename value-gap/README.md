# Courtside · Value Lab

For opening the app, using its controls, and updating projections, see the [step-by-step user guide](QUICKSTART.md).

A standalone points-league tool, hosted at [GitHub Pages](https://thomrp.github.io/depth-chart-wall/value-gap/). Import your saved projection JSON on the first visit. You can also open `value-gap/` from a static HTTP server; the existing depth-chart `index.html` and `worker.js` are unchanged.

The two lists compare current per-game production against **Combined ROS (50/50)**, **Hashtag pure ROS**, or **standalone DARKO daily projections**. Combined ROS uses Hashtag's minutes and averages Hashtag and DARKO counting-stat rates. Each player shows current stats, the selected projection, and current-minus-projected differences, including fantasy points. The source switcher retains both manual imports and the locally calculated combined baseline, each with separate scoring settings. League coefficients recalculate both FPTS rows and the rankings. Penalties such as turnovers reverse favorable colors while preserving the actual signed stat difference.

The private review site starts with the user-supplied NBA projection snapshot. A fresh public-code checkout starts empty. The private app checks for updated saved snapshots when reopened, so its earlier baseline upgrades without clearing browser settings. Explicit manual imports and cleared data remain under the user’s control. Choose **Data sources** to import your own datasets; no fictional player data is loaded. Choose **League scoring** to configure points. New imports and scoring persist in the current browser’s local storage; clear imports from Data sources. The supplied initial snapshot is packaged only in the owner-private Site, not in this public repository. Imported projections are never sent to the stats worker or the hosting server.

## Data input

**Combined ROS** is built locally when the user has manually imported Hashtag pure ROS and DARKO per-game projections for the same season. For each matched player, `DARKO rate = DARKO stat / DARKO minutes`, `combined MIN = Hashtag MIN`, and `combined stat = (Hashtag stat + DARKO rate × Hashtag MIN) / 2`. This is equivalent to averaging the two per-minute rates and multiplying by Hashtag minutes. It does not average source minutes, or source FP/G values. Source matching uses the same strict identity/name rules as current-stat matching. Only unique matches with positive minutes in both sources enter the combined set; excluded names and unused DARKO rows appear in a coverage report. Hashtag supplies team, position, and player identity.

Missing DARKO categories use the available Hashtag value with explicit per-category provenance, including the four shot-volume columns missing from the supplied CSV. Missing Hashtag categories remain null and can prevent a player's FPTS calculation. FG%/FT% follow the resulting made/attempted counts, with a Hashtag percentage fallback when volume is missing; percentages are never scaled by minutes or used to infer volume. Each combined player card has an expandable input table showing Hashtag per-game stats, DARKO per-minute rates, DARKO at Hashtag minutes, and the final projection. The current/projection/difference rows and projected-FPTS filter all use the combined result.

The combined baseline initially inherits saved Hashtag scoring, preserving full shooting-volume weights rather than inheriting reduced standalone DARKO scoring. Subsequent scoring edits remain source-specific. Updating either raw import rebuilds Combined ROS and preserves its selection and scoring. Reopening the browser recomputes from the saved pair with a stable content revision for the current-stats cache. Incompatible seasons or inputs remove a stale combined baseline and show the reason. Importing the second source, or upgrading an older session that has both, selects Combined ROS the first time; standalone source selection is preserved on later reloads. Combined calculation archives cannot be imported as a replacement for the two original sources. No new projection feed, Worker, authentication, or background projection download is used.

**DARKO Fantasy Lab CSV** is detected from its export headers (`Rank,Player,Team,Pos,Min,PTS,REB,AST,STL,BLK,3PM,FG%,FT%,TOV,FP/G`). Import it in the Projections tab, select the season ending year, and confirm per-game inputs. The supplied 338-player export maps all player identities to ESPN; projections without GP do not affect the current-games filter. Full team names become NBA abbreviations. DARKO's G/F/C positions get broad filters without inferred fine position eligibility. Its baseline remains daily rather than ROS. Reimporting replaces only the DARKO snapshot; manual imports remain in browser storage and are not published with the app.

The supplied DARKO CSV lacks **FGM/FGA/FTM/FTA** and scoring coefficients. Percentages never imply shot volume. When active scoring needs those columns, a visible warning blocks ranking and offers a scoring review with the missing weights set to zero. Applying that form explicitly opts into reduced scoring for both sides, saved only for the selected source. Hashtag scoring remains available when switching back. Source `FP/G` is retained as `sourceFpts` in JSON but never overrides computed FPTS. FG%/FT% display with shooting stats, including differences in percentage points, without adding percentage scoring. [DARKO's Fantasy Lab](https://www.darko.app/projections) describes the projected minutes and pace used for its per-game conversions. The CSV has no season or as-of timestamp, so imports record their import time and require a season selection.

Accepts a complete saved Hashtag HTML page (including page source saved as `.txt`), JSON, CSV, or a tab-separated copied table with headers. HTML is parsed in a detached document; only table data and whitelisted source/scoring selections are extracted. Scripts, account fields, and raw HTML are discarded. Source kind, season, per-game basis, player-limit coverage, full names, and supported enabled scoring coefficients are detected from saved selections. A projection library shows real imported players while current data is still missing. Hashtag aliases include `PLAYER`, `POS`, `TEAM`, `GP`, `MPG`, `PTS`, `TREB`, `AST`, `STL`, `BLK`, `TO`, `3PM`, `FG%`, and `FT%`. Percentage cells with `(made/attempted)` preserve shooting volume. Select the correct NBA season ending year and confirm per-game inputs. Explicit totals, BLEND projection metadata, and conflicting source seasons are rejected. Select **Any** for minimum games if your current source lacks GP.

See [Hashtag findings and exporter](HASHTAG.md). Use the exporter on the table you can already view while logged into your own account. It downloads JSON without collecting credentials. The user-supplied logged-in page source has been successfully parsed; automated authenticated fetching is still unverified. A full ROS import must be selected and verified by the user; the application does not substitute the public top-30 table or claim it is a complete feed.

```json
{
  "metadata": {"source":"My ROS snapshot","basis":"per-game","season":2027,"horizon":"rest-of-season"},
  "players": [{"name":"Example Player","team":"BOS","position":"SF","games":8,
    "stats":{"min":32,"pts":20,"reb":6,"ast":4,"stl":1,"blk":0.5,"tov":2,"fg3m":2,"fgm":7,"fga":15,"ftm":4,"fta":5}}]
}
```

Current-stat imports use the same shape with `metadata.kind: "current"` and `metadata.period: "season"`, `"14"`, or `"8"`. Worker windows `8` and `14` mean appearances. Hashtag Last N days sources use distinct `days-7`, `days-14`, and `days-30` metadata, so days are never mislabeled as games. The app does not resample imported averages when changing a window; import the correct source table for each window.

Current stats connect automatically to `https://value-gaps.thomrisped.workers.dev` after ROS projections load. The app uses its bundled public ESPN identity directory, so the Worker’s optional `/roster` proxy is not required. This avoids the observed `roster_http_404` / HTTP502 failure before stats requests. The app refreshes every 15 minutes while open, with a visible progress/error message, a Refresh NBA stats button, and season/last-14-games/last-8-games windows. Fresh cached results avoid redundant fetches; players publish progressively as batches finish, overloaded requests retry in two-player groups, and failed requests preserve successful rows. Previous same-window rows can remain visible when their update fails; they are labeled CACHED with a warning and their original timestamps. Wrong-season responses never enter the comparison. Manual current-stat imports stay selected until the user explicitly switches to NBA stats. For another deployment, use the separate [Worker](value-worker.js) with [WORKER.md](WORKER.md), then change its URL in Data sources. It batches up to 20 ESPN IDs per request and checks the requested season. The app matches stable IDs within their source namespaces, then unique normalized names; ambiguous matches stay excluded and are reported. Explicit Nic/Nicolas Claxton, Alex/Alexandre Sarr, and Ron/Ronald Holland aliases resolve verified naming differences. Stable ESPN profile IDs supplement the depth chart for injured or absent players, so their game logs can still be requested. This covers all 300 identities in the supplied snapshot. Future unmatched players are reported without guessed identities or invented statistics.

## Calculation and limits

`FPTS = Σ (per-game stat × league weight)` and `gap = current FPTS − projected FPTS`. Players missing a nonzero weighted stat cannot be ranked. Zero projection baselines have no percentage gap. Filters support name, team, position, games played, and an inclusive minimum projected FPTS per game using the current source's scoring. The projected minimum accepts typed numbers with one-point spinner steps, is remembered in the browser, and clears to show all players when left blank. It applies to both lists, the projection library, and filtered CSV export. Sorting supports absolute FPTS gap and percentage gap. CSV export identifies the selected provider and contains the filtered comparison with all three rows; percentage values and their differences are fractions.

The first version supports additive per-stat points, including made/attempted shooting and minutes when supplied by the source. It does not score percentage categories, double/triple-double bonuses, or estimate market trade prices. The selected projection baseline is treated as the source of truth; the combined option is the specified equal-rate average and adds no further regression model. Hashtag's own BLEND/STREAM tables remain unsupported as the Hashtag input.

```sh
npm ci --prefix value-gap
npm test --prefix value-gap
node --check value-gap/app.js
node --check value-gap/hashtag-export.js
```

Parser, scoring, matching, and Worker tests use fixtures. The HTML importer and hosted-snapshot upgrade tests use sanitized synthetic fixtures. Current-stat caches are tied to the saved projection revision, so a broader baseline triggers fetching stats for the newly included players. Browser QA covers the actual supplied page-source import. Automated Hashtag authenticated fetching remains unverified. The user-deployed stats Worker returned valid live 2026–27 responses for Jokic and Doncic. The development environment cannot reach the new Worker hostname, so the full automatic browser flow is also verified with controlled responses and that real two-player sample; full live batch results need confirmation from the app in the user’s browser. Production has no npm runtime dependencies or build steps; linkedom is a development dependency for HTML parser tests.
